## 2. 优先修复：矮窗口下会话定位提前完成

### 新版变化

rc.2 将侧栏调整为外层导航滚动区与内层会话滚动区协同滚动：

- `packages/client/ui-sidebar/src/client/SidebarRoot.tsx:405` 引入外层 `data-sidebar-scrollport`。
- `packages/client/ui-sidebar/src/client/scroll-handoff.ts:55` 实现滚轮交接。
- `packages/client/ui-workspace/src/client/rows/WorkspaceBrowser.module.css:350` 将内层滚动职责移到 `.listArea`，`.list` 在第 388 行改为 `overflow: visible`。

### 主题冲突与复现

主题 `src/styles/prts.css:856` 仍对树设置 `overflow-x: hidden`。当原生纵向溢出值为 `visible` 时，浏览器会把计算后的 `overflow-y` 变成 `auto`。它因此成为一个没有自身纵向滚动余量的滚动祖先。

`src/client/session-card-reveal.js:46` 起只寻找第一个纵向滚动祖先，并在该范围内判定卡片可见；没有验证外层侧栏是否仍在裁切。调用方的扫描根是 `sidebar.workspaces`，并不包含外层导航滚动区。

真实 rc.2、1440×560 窗口，使用现有会话卡片与当前仓库的原函数，仅替换测试回调，不打开目标会话：

| 状态 | 卡片顶部/底部 | 外层可见顶部/底部 | 完全可见 |
| --- | --- | --- | --- |
| 定位前 | 577 / 611 | 116 / 506 | 否 |
| 主题定位回调完成后 | 577 / 611 | 116 / 506 | 否 |
| 原生 `scrollIntoView({ block: 'nearest' })` 后 | 472 / 506 | 116 / 506 | 是 |

另一个独立页面中，仅临时把该树的 `overflow-x` 改为 `clip`：计算值由 `hidden/auto` 恢复为 `clip/visible`，不修改定位函数即能让卡片到达 472 / 506，完整可见。这验证了 CSS 与新版滚动结构的具体冲突，而不只是推测嵌套滚动有风险。

影响是“先定位卡片、再切换会话”的可见性保证失效，不是会话打不开或数据丢失。

建议先移除不再合适的滚动容器制造规则，再让定位逻辑验证实际裁切链；不能直接禁用宿主的滚轮交接。补充低高度、外层未滚到底、会话展开及手动滚动中断的回归，避免仅修复一个尺寸。

## 3. 首页鲸鱼与主题动效策略未联动

处理决定：用户随后明确表示此项可以不处理。保留原生鲸鱼及现有偏好边界，不纳入本轮适配修复；其实现方式仅作为未来自有装饰效果的参考。

### 新版变化及实际表现

- 新增 `conversation.hero.frame` HOC，官方品牌插件挂载 `data-home-whale` 画布；相关源码为 `packages/client/ui-brand-official/src/client/home-whale/PixelWhale.tsx`。
- 主题首页已有粒子画布，同时仍存在原生鲸鱼画布。点击空白区域会请求 `breach-atlas-43c5305a3d4d.webp`，HTTP 200，随后播放原生动效；原生安全模式也有同样行为。
- 重新检查确认主题的 `data-prts-hero-active` 与粒子层正常存在。新包裹层没有导致首页识别整体失效，不能仅凭原生品牌标题仍在就判定主题首页坏了。

### 动效偏好边界

原生 `renderer.ts:32` 只读取系统 `prefers-reduced-motion`；`play()` 在第 187 行检查这一媒体查询、可见性和播放状态。主题的减动效偏好则还包括 `preferences.motion === 'reduced'`，并通过 `src/client/theme-controller-v2.js:768` 写入根节点 `data-prts-motion`。

浏览器中保持系统媒体查询不减动效，仅临时设置主题相同的根标记 `data-prts-motion="reduced"` 后，空白点击仍触发图集加载。此实验验证的是“主题减动效状态标记未被原生装饰消费”，没有通过写入共享设置模拟完整偏好保存流程。

390×844 窄屏下另做系统偏好对照：系统减动效时图集请求为 0，系统不减动效时为 1，两组均保留主题首页激活标记且无页面异常。这进一步说明原生系统偏好生效，缺失的是主题自身的偏好联动，而非原生完全不支持减动效。

这是装饰与偏好策略的整合缺口，而非发送故障。原生动画是首次播放才加载图集、按需播放，不能描述成闲置时永久运行的动画循环。

建议主题启用时明确选择由谁负责首页装饰；至少减动效模式应抑制原生装饰的播放。仅透明隐藏画布不保证停止其内部渲染或加载。新增 HOC 可作为整合入口，但不是已经存在一个可任意卸载其他插件层的接口，不宜据此大改整个主题。

## 4. 新文件搜索设置面板未接入主题浮层材质

### 新版变化与复现

新增文件搜索、隐藏文件控制、忽略规则与搜索设置；原生提供 `data-files-search-settings` 等稳定标记。

`packages/client/ui-sidebar-files/src/client/SearchSettings.tsx:54` 使用内嵌的 `section[role="dialog"]`，没有 `aria-modal="true"`，不是独立 body portal。

主题 `src/client/floating-glass-adapter.js:13` 的候选集仅包括菜单、列表框、模态 dialog 与 popover，因此漏掉这个面板。

真实 1440×950 页面，打开右侧文件面板、搜索栏及搜索设置后：

- `data-prts-floating-glass` 为空。
- 背景为原生 `rgb(8, 10, 12)`，`backdrop-filter: none`。
- 面板中的文本输入与复选框没有浮层适配器标记。
- 面板可正常打开和显示规则；这次没有修改忽略规则、隐藏文件或搜索偏好。

它是视觉材质/控件覆盖缺口，不是文件搜索功能失效。原生内嵌面板的尺寸和定位仍应由宿主管理。

390×844 窄屏复测相同缺口；面板边界为 x=9、右边界 382、顶部 118、底部 836，没有越出视口。因此没有证据将它升级为移动端布局不可用问题。

建议基于 `data-files-search-settings` 定点纳入适配，并为组合式搜索输入补齐焦点态和主题配色；不要把所有非模态 `role="dialog"` 无差别当成模态弹窗，更不能补上假的 `aria-modal` 来匹配旧选择器。

## 5. 基于 rc.2 的优化机会

### 5.1 使用新增语义 token，减少跟随私有 DOM 的覆盖

新版 `packages/client/ui-theme/src/styles/design-platform.css` 增加选中边框、卡片填充、HoverCard、JSON 树、图表等语义变量，例如 `--dsw-alias-border-selected`、`--dsw-alias-card-fill`、`--dsw-alias-hovercard-bg`。

主题目前只有少量原生 alias 映射。可以优先为新增原生界面补齐必要的语义变量，再保留 PRTS 自有卡片与布局，不必每新增一个控件就增加 class 片段选择器和 DOM 观察器。这是可维护性机会，不是要求重写主题系统；也不应统一覆盖错误、警告等语义色。

### 5.2 保留原生 diff/math 渲染，把定制放到正确边界

新版支持 diff/patch 栅栏的增删行样式、数学栅栏，以及 `conversation.chat.markdown.fence` HOC。

原生 `CodeBlock` 保留主题已使用的 `.md-code-block`、`data-code-block-banner`、`data-code-block-content`；暂未发现这些入口直接失效。增删行通过 `--dsw-alias-file-diff-added-*` 和 `--dsw-alias-file-diff-deleted-*` 保留语义背景与标记。

建议补充浅色/深色背景下的 diff 行对比度、横向滚动、换行和流式 math 完成状态验收。确需新增代码工具条时优先考虑正式 fence 扩展边界，不要为了统一玻璃背景抹平增删信息。新增的两个 HOC 只覆盖首页框架与 Markdown 栅栏，不能用来替换整个助手消息观察器。

## 8. 后续修复：矮窗口会话定位

用户在真实状态总览跳转中确认了问题，并要求修复。以下记录属于审计之后的实现与部署，不改变前述审计阶段的验证边界。

### 最终实现

- 首要定位目标只选择确实有纵向滚动余量的祖先，不再把仅有 `overflow-y: auto` 计算值、实际不能纵向滚动的树当作目标。
- 导航前继续检查整个侧栏范围内的纵向裁切祖先，包括 `sidebar.workspaces` 之外的原生导航滚动区；必要时用原生 nearest 滚动补齐外层可见性，等待相关滚动稳定后完成定位。

- 初始尝试将横向裁切改成 `clip`，但扩展回归发现它会影响 148px 极窄侧栏的菜单交互，因此已撤回。最终没有修改 CSS，而是在定位逻辑中正确识别实际滚动能力，保留原有横向裁切和宿主滚轮交接。
- 重建 `lib/client.js`；浏览器构建比公开基线增加 1460 字节，包体预算对应增加 1.5 KiB，没有新增依赖或调整版本号。
