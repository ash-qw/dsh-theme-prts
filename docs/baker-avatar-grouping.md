# Baker 每轮头像合并（issue #6）

## 行为

“合并过程回复头像”保持默认开启，但合并范围调整为每一轮回复：只为首条可见、有内容的 AI 正文显示头像。最终回答不再独立保留头像；若它是该轮唯一可见的正文，仍显示头像。新版默认“全部回复”下，工具 / 推理折叠不改变正文可见性，无需重新选择头像；“仅最终回答”等场景实际改变正文显隐时才重新判断，不将头像放到“工作步骤”组头。

可见 user / steering 输入开启新一轮；隐藏输入不重置计数。不同 `data-conversation-scroll` 作用域分别计数。关闭开关或停用适配器时清理所有隐藏标记，恢复原有逐条头像。

## 实现边界

- 不再依赖 `data-turn-process-member` 或 `data-chat-turn` 分组。因此宿主默认“全部回复”和“仅最终回答”使用同一规则，不修改宿主偏好。
- 同时处理 `assistant-step` 和旧版 `data-message-role="assistant"`，对同一作用域内的嵌套别名去重；角色改变、卸载、分页移除后清理旧标记。
- 无正文、纯工具栏和 reasoning 不占头像名额；纯图片等媒体回复可占用名额。流式首行从空变为有内容时，头像转移回首行；内容被清空后转移到下一条正文。
- 复用原有 MutationObserver 与帧合并调度，不增加观察器、轮询或布局读取。排除仅工具 / 推理的显隐、内容更新和无关菜单类名变化；非空正文的流式增长及空白文本更新不触发头像重扫。正文显隐、轮次边界、消息增删、角色及正文资格变化仍会重新分配。
- 需要重新分组时仍遍历当前已挂载的消息，并未改为逐轮增量算法；头像重扫本身不受玻璃 surface 标记的 4ms 分片预算约束，不将跳过无关扫描表述为所有长会话开销已消除。
- 分页依据当前已挂载 DOM 的输入边界重新分配；尚未加载的历史内容不参与计数。不更改消息、气泡位置、背景材质、侧脊动画或会话快捷操作策略。
- 设置键、默认值、配置格式和主题版本不变；DSH 支持范围收窄为 `0.2.2-rc.1`，只以新版 Web 的实际验证为准，不将旧 DOM 夹具视为旧版宿主验收；“最终回答不再独立保留头像”是有意的可见行为调整，取代 1.3.1 引入时的旧规则，不重写历史发布记录。

## 验证

- 初始修复前先复现默认“全部回复”下每条正文各带头像的问题；性能优化前新增断言同样先复现工具 / 推理折叠和空白更新触发无关重扫。
- 适配器单元测试 30 项通过，包含首轮新增的 8 项分组边界和本轮新增的 7 项失效条件 / 清理验证；`npm run check` 共 453 项通过。
- 最终构建选取的 75 项 Chromium 回归全部通过，包含 13 项 Baker 头像专项，以及气泡、头像材质、代码 / 表格、用户消息、透明背景、浮层、侧脊与新版主栏。覆盖默认全部回复 / 仅最终回答、日夜、1440 / 390px、流式、分页、独立作用域和开关持久化。
- 浏览器扫描次数断言：连续折叠 / 展开仅工具及推理内容，头像整段重扫次数为 0；同样操作实际隐藏中间正文时，每次操作按帧合并为一次重扫，头像正确转移并恢复。相关单测还覆盖无关菜单类名、工具内容增删、非空正文内空白变化、关闭合并和 reasoning 移除后的标记清理。
- 明确排除两项已在修复前的 `87e0fdd` 构建独立复现的旧测试：经典徽记测试读取旧 localStorage 字段；头像重置测试仍按原生 confirm 处理，遗留的页面内确认框阻挡后续点击。本轮不把这两项写为通过，也不顺带修复无关断言。
- Baker 开关持久化测试使用当前原生 configForms 夹具，验证关闭后恢复逐条头像及刷新后设置保留；旧 DOM 回归夹具不等于旧版 DSH 实机验收。
- 本轮客户端较优化前增加 1,654 字节（约 1.62 KiB），体积预算显式增加 2 KiB 用于正文相关性判断，不引入运行依赖、额外观察器、轮询或新视觉效果。
- 已部署本地 DSH Web `0.2.2-rc.1`，服务 `running healthy`；已安装客户端与浏览器实际获取的完整客户端均匹配当前构建，安装的 `engines.dsh` 也是 `0.2.2-rc.1`，无关依赖图不变。
- 最终部署后只读检查一个已有多步会话：42 条可见 AI 正文、7 个回复分组，每组恰好一个头像，无页面异常；不发送模型请求、不改消息、不变更宿主 foldedReplies 设置。此前原生过程组交互检查未确认有工具 / 推理节点实际改变显隐，不作为真实折叠生效的验收证据；折叠语义与扫描次数以浏览器夹具验证为准。
- 不宣称全量浏览器、用户 Edge 帧率或 macOS 官方桌面端实机验收通过。

## 专项性能测量（2026-11-06）

本机无头 Chromium 140.0.7339.186，使用合成会话 DOM，不包含宿主 CSS。对照组保持相同的头像分组语义，仅恢复优化前的失效判断；交替运行新旧实现，排除预热后每组统计 48 次操作。耗时是适配器 MutationObserver 回调与调度扫描的主线程执行时间之和，不含帧等待、绘制和合成，不能等同于 Edge 实机帧率。

| 场景 | 优化前中位数 | 优化后中位数 |
| --- | --- | --- |
| 100 条正文，仅工具 / 推理折叠 | 1.4ms | 0.2ms |
| 500 条正文，仅工具 / 推理折叠 | 4.7ms | 0.1ms |
| 1000 条正文，仅工具 / 推理折叠 | 5.9ms | 0.1ms |
| 1000 条正文，实际折叠中间正文 | 6.7ms | 8.2ms |

- 每个规模下，仅工具 / 推理折叠的头像整段重扫均从 48 次降为 0 次；正常非空文字流式增长，新旧实现均为 0 次重扫。
- 实际折叠中间正文时，新旧实现均重扫 48 次，1000 条正文样本中新版耗时反而更高；本轮没有改善这个分支，不能据此宣称所有场景都更快。
- 结论仅限默认工具 / 推理折叠路径的适配器开销显著降低，不保证整页帧率或长会话中所有操作无掉帧。
