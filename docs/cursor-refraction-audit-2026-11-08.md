# PRTS 局部水波折射验证（2026-11-08）

本记录描述定点弧线反馈之后增加的水波折射。早期样式失效根因、Shadow DOM 隔离及历史性能对照见 `cursor-feedback-audit-2026-11-07.md`，其中的测试数量与部署哈希是当时的记录。

## 实现与边界

- 保留现有粗细变化、渐细缺口、三圈扩散及相近弧线的增强 / 抵消；可交互控件仍使用原有完整按压动画，折射只用于非交互区域显示手形光标时的点击反馈；文本光标（含只读正文）不触发水波，正文空白处若显示手形仍可触发，不影响已有波源继续播放。
- 每个波源额外添加一个局部折射节点，与外圈在 560ms 内同步扩散和淡出；最多三处，且不跟随鼠标。整个反馈仍约 650ms 后清理。
- 使用 `backdrop-filter` 引用同一 Shadow DOM 中的 SVG `feDisplacementMap`，直接折射已经绘制的真实背景；不截图、复制或重新渲染会话 DOM，不增加模糊、实色底板或全屏常驻水面。
- 径向位移图在构建时生成，96×96，编码到缓存 PNG；围绕波峰编码正 / 负径向位移，圆心和边缘保持中性，外缘平滑收敛，避免方形边界接缝。滤镜 scale 为 9，波带扩宽并平滑收敛，主扩散阶段保持折射强度、末段才淡出，产生可见的数像素位移；纯色背景本就不易观察，应在文字、卡片边缘或纹理背景附近体验。
- 仅折射动画新增一个 WAAPI transform / opacity 动画，不新增逐帧 JS、计时器或 DOM / SVG 属性更新。背景采样和滤镜本身仍有浏览器渲染成本，不能据此声称零开销或一定由合成线程独立完成。
- 弧线干涉仍由局部共享 WebGL 图层计算；背景折射是各波源的局部近似，并非完整流体模拟，不宣称背景位移满足同一物理叠加方程。
- 不通过背景滤镜语法能力检测时不创建滤镜或折射节点，保留弧线反馈。该检测不是所有引擎实际 SVG 位移能力的保证；本轮验证为 Chromium，不扩大 DSH 或浏览器支持声明。
- 模式切换、关闭动画、减少动效、取消、失焦及销毁沿用既有清理机制；折射动画与波源一起取消，稳定宿主中的滤镜定义随宿主释放。原生 dialog / popover 保持可见，焦点、命中与文本选择不变。

## 用户反馈后的可见性修正

用户反馈首版看不出区别。复查真实会话而非仅依赖高对比网格后发现：首版虽然存在像素位移，但整体缓动让 180ms 时的折射透明度已降至约 28.2%，同时位移较弱、波带过窄，正常点击难以感知。这不是仅凭 CSS 属性存在就能认定效果达标的问题。

- 位移强度由 3 调整为 9，径向波带扩宽并保留中性圆心、平滑外缘；折射在扩散阶段保持强度，末段才淡出。弧线本身的亮度和原有按压动画不变。
- 未增加节点数量、最大折射矩形、动画时长或逐帧 JS；仍不使用截图、模糊或实色底板。这不代表 GPU 成本必然完全相同。
- 同一真实会话、同一点击位置和 180ms 采样，隐藏弧线后只开关生产折射滤镜：220×220 区域中 RGB 绝对差总和大于 20 的像素由 34 增至 446；透明度从 0.282256 变为 1。该像素数量不是物理位移或性能倍率，截图仅是一个固定时刻的诊断。
- 新增真实直边回归：保持生产参数，不人为放大滤镜，要求至少 9 行出现不小于 2px 的可见边缘位移；避免仅证明抗锯齿像素变化就判定折射有效。日 / 夜、原生 dialog / popover 的波带位移测试同时要求 180ms 时折射透明度至少为 0.9。
- 诊断数据为 `/tmp/prts-water-visible-before.json`、`/tmp/prts-water-visible-after.json`，生产直边截图为 `/tmp/prts-water-visible-edge.png`。
