# 文件预览文本光标补漏

> 首轮逐字命中方案因卡顿反馈撤回，以下首轮实现与部署记录为历史记录；后续按用户确认改为 CSS 文本区域方案，见本文末尾。

日期：2026-11-21。用户反馈 Python 文件预览仍没有正确显示主题文本光标，核对本地 DSH `0.2.2-rc.5` 的真实预览组件后修复。

## 原因与修复范围

- 原先仅接入普通文本的 `data-textpreview-plain` 与 Markdown 的 `data-document-markdown`，不能据此推断所有源文件已经覆盖。Python 等受支持源文件实际走独立的 `CodeBody`，外层标记为 `data-code-preview`。
- 将代码预览内的 `data-code-block-content` 加入文本命中范围，继续使用相邻字符矩形检查，只对实际字形切换主题 I 形光标，不把代码预览整个面板或工具栏作为文本区域。
- 不添加扩展名白名单，宿主使用同一代码预览器呈现的其他语言一并适配。保留工具栏按钮、行号、空白、不可选内容与系统光标模式的原有行为；不改问答档案卡设计。
- 更新中英文说明与客户端构建，版本保持 `4.2.1`，DSH 支持范围不变；未提交、推送或公开发布。

## 第二轮：CSS 文本区域方案

- 用户确认回滚后重新打开浏览器不再卡顿，并同意改为按内容语义适配，不再坚持仅在实际字形上显示文字光标。
- 在普通文本、Markdown 与代码正文根区域设置可继承的主题 I 形光标，不对后代元素逐个覆盖，也不维护文件扩展名白名单。正文中的行尾与空白一并显示文字光标；按钮、链接、输入框、显式拖拽区域和不可用控件保留原有光标。工具栏、显式文本交互排除标记与行号装饰单独保留手形默认光标。
- 文件预览在进入聊天正文命中算法前直接退出，不再调用光标插入点 API 或测量字符矩形，不再因文字命中写入 `data-prts-text-hit`。即使预览嵌套在会话结构内也跳过。聊天正文、输入框和其他既有光标行为不做整体重写；图片等非文本预览不套用正文样式。
- 新增单元回归核对四种预览根标记下的移动、滚动和点击均不进入字符定位。浏览器检查改为在尚未移动鼠标时验证 CSS 已生效，并覆盖行尾空白、控件、禁用态、图片预览排除、缩放、拖选、滚动和系统光标切换。
- 最终 10 项预览结构浏览器专项通过，包含 8,000 行 Python／JSON 样本的持续移动、滚动和移出后空闲采样：插入点 API 调用、字符矩形测量与预览文字命中属性变更均为 0。限定采样窗口内帧数超过 20、最大帧间隔和长任务均低于 1 秒；这是严重停顿回归阈值，不是 60 FPS 保证。相邻 9 项既有光标浏览器回归通过。
- 验证按单 worker 顺序运行，不将全量单元测试与浏览器测试并行执行。此前全页卡顿的确切根因仍没有故障现场性能录制，不能将本轮结构性简化描述为已经证明旧故障的具体原因。

## 第三轮：右侧预览范围收紧试用

- 用户要求先只在右侧边栏文件预览试用折中方案，不改会话正文。新规则限定于 `data-textpreview-body` 内；独立 Markdown 容器与会话的字符命中逻辑不变。
- 不插入包装节点，也不改 React 管理的文本节点。通过 CSS 的 `inline-size: fit-content` 与 `max-inline-size: 100%` 收窄普通文本行、代码行、Markdown 段落／标题／列表项等现有盒子；正文容器保持默认光标，短行右侧和正文外大块空白不再继承 I 形光标。行号与空的代码行保持默认光标，按钮、链接、输入框和拖拽规则保留。
- 这是按行／段落盒子收紧的保守试用，不是逐字轮廓命中，也不是将所有文字转换为行内包装。缩进、实际空格、行内留白以及自动换行段落或代码行的部分末行空白仍可能显示 I 形；表格单元格保留单元格范围的文字光标。
- 不判断文件后缀、不增加鼠标位置检测或字符矩形测量，没有新增 MutationObserver。文件切换、分页追加与高亮更新沿用宿主原有渲染，CSS 自动匹配新增的行／段落。
- 部署前候选客户端的两项深浅色原生预览测试通过，覆盖六种代码语言、普通文本与 Markdown 短行末尾的真实鼠标落点；正常动效下验证较大 JSON 的移动／滚动／空闲采样，并比较自动换行代码切换前后的文字矩形，样本布局一致。首轮扩展原生测试时遗漏了隔离上下文中 Markdown 注册回调，导致测试组件未挂载；补齐测试注册后重新运行通过，并非忽略失败用例。
