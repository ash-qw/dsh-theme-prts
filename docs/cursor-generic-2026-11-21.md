# 插件正文通用光标兜底试用

## 范围与取舍

- 起点为已验收提交 `b1306c7`；本轮按用户要求试用通用兜底，不再为伙伴或其他插件添加专有选择器，也不修改伙伴插件本身。
- 现有会话、文件预览和 CSS 已指定的主题文字光标继续走原规则；其余普通 DOM 内容按鼠标附近的文字片段矩形识别。不缩短第三方插件段落，不包装文字节点，仅切换当前命中元素的临时光标标记。
- 按钮、链接、表单、工具栏、禁用态、不可选择文字、非文本预览及明确的原生拖拽／缩放光标优先排除。可聚焦的只读代码和滚动表格不能仅因 `tabindex` 而被排除。
- 兜底不是纯 CSS，也不是旧的逐字符测量：每次最多测量当前文字节点附近 2,048 个 UTF-16 单元，超过 128 个片段时保留原光标并退避 250ms。探测耗时超过 8ms 时抑制接下来的新探测；不能中断浏览器正在进行的单次原生布局，因此不是硬实时上限。
- 连续移动沿用原有每帧合并调度；缓存最多保留 160ms，复用前核对元素盒子。仅当前元素使用内容变更和尺寸观察，滚动、缩放及局部内容变化按帧刷新；没有整页扫描、逐字遍历、全局常驻内容观察或空闲轮询。离开、切换系统光标和卸载时清理缓存、观察器和临时标记。
- 普通空格仍可能位于文字矩形内；没有角色语义也未声明正确光标的自定义点击区域不能可靠推断。独立 iframe、画布文字及封闭 Shadow DOM 不承诺自动覆盖。

## 验证设计

- 单元测试覆盖矩形缓存、110 万字符节点的有界片段、过多片段退避、交互优先、滚动／尺寸／文字失效、旧插入点 API、异常降级及单帧合并。
- 浏览器覆盖两种配色和会话样式下的普通段落、无标记 div／span、折叠内容、可聚焦代码、表格、行尾空白、控件、拖选、流式替换和系统模式退出，同时比较元素几何与原文不变。
- 较长单节点样本统计实际片段长度、测量次数和空闲期不增长；已有长会话及大文件样本继续要求 CSS 管理范围内插入点／字符测量为零。帧间隔粗阈值仅排查严重停顿，不代表 60 FPS 保证。
- 真实宿主测试只打开已安装伙伴工作区并悬停只读文字、空白与导航控件，不创建伙伴、不发送消息，也不写入用户持久化设置；同时保留原生会话与预览回归。

## 验证结果

- 最终 `npm run check`：构建及 673 项单元测试通过，0 失败、0 跳过。客户端比 `b1306c7` 增加 2,803 字节，按既有包预算约定显式为通用片段探测增加 3 KiB 配额，没有新增依赖。
- 30 项浏览器回归分别通过：集中运行通过 29 项，调整后的较长单节点压力项独立重跑通过。最初的超大浏览器样本在主题注入前已超时，因此改为约 5 万字符的浏览器样本与 110 万字符的单元样本分开验证，不把未完成的样本写成性能验证通过。
- 普通正文覆盖深浅色、经典与 Baker，以及 80%／100%／125% 缩放；断言文字、元素几何不变，展开正文和可聚焦代码／表格可命中，明显行尾空白及控件不被文字光标覆盖。
- 会话与预览的零探测断言限定在其实际 CSS 管理范围；预览外的只读路径、文件名会进入新兜底，不再错误要求整页都没有文字命中标记。通用用例另行检查片段上限、缓存与移出后空闲期没有新增测量。
- 两项原生会话／预览候选回归通过；伙伴真实展开工作区两项深浅色候选回归通过，检查文字、明显空白、控件和几何一致性，没有持久化写入或页面异常。

## 通用兜底性能优化

用户确认未知插件也需保留主题光标，因此继续使用通用按需探测，不改成系统光标兜底，也不新增逐插件适配。

- 完整覆盖唯一文字子节点时，缓存同时回答文字命中与行尾空白未命中；多个子节点或仅覆盖部分长节点时不能据此跳过其他文字。
- 空叶节点与不超过 2,048 单元的纯空白文字不查询插入点，但继续局部观察，内容到达后仍能刷新。
- 新插入点探测至少间隔 32ms；缓存命中仍立即处理。限频期间只保留一个延后刷新，鼠标停止后也会处理最后位置；退出、进入控件、切换系统模式及卸载时取消。延后刷新不是空闲轮询，不会自行周期性续订。
- 滚动、尺寸与局部内容变化先失效缓存，再由共享动画帧读取 `elementFromPoint`；一批事件不在回调中抢先读取布局。没有 rAF 的环境保留同步降级。
- 原有 160ms 缓存、2,048 单元片段上限、128 片段退避和慢探测保护不变。32ms 为正常情况下的新探测启动间隔，不是延迟硬上限；复杂浏览器布局仍无法被中途打断。

### 优化验证

- 新增空叶节点到达文字、连续空白缓存、单次延后刷新、跨节点不误判、慢探测恢复、退出清理与滚动／尺寸事件合并等回归。延后刷新不能主动失效尚有效的片段缓存，否则限频可能反而增加矩形测量。
- 全量检查执行 681 项，680 项通过，唯一失败为构建体积配额。精简实现后重新构建，并重跑光标与打包相关 51 项，全部通过；没有上调体积配额，也没有将未重跑的整套检查写成最终全绿。
- 最终构建为 1,432,914 字节，比首次通用兜底增加 547 字节。31 项浏览器回归全部通过，包含深浅色、两种会话样式、缩放、控件、拖选、流式变化及长会话／Python／JSON 预览的零插入点查询。
- 同一 Chromium 中按帧发送 60 次短段落行尾空白移动：优化前插入点查询 60 次、片段测量 7 次；优化后插入点查询 7 次、片段测量仍为 7 次。该结果说明减少了重复插入点查询，不代表整体 CPU 占用降低相同比例。
