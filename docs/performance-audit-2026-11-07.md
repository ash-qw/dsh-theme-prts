## 归因证据

### 不是侧栏被禁用，也不是只在等待网络

目标加载期间，侧栏没有 `inert` / `aria-disabled="true"` 祖先，计算后的 `pointer-events` 为 `auto`。正文和侧栏属于同一页面主线程，正文的同步工作仍然会推迟侧栏事件处理。

独立输入诊断中，从短会话切入后约 0.80 秒通过 CDP 向侧栏注入一次指针移动，实际侧栏事件处理发生在约 2.71 秒，事件时间戳到处理回调间隔约 **1.91 秒**。已确认事件目标属于侧栏，不只是光标位于侧栏坐标。该合成输入诊断不计入正式对照表，也不是 Edge 物理设备的输入延迟；它直接复现了侧栏事件排队，而非侧栏 disabled。早先一次指针探针未命中侧栏、一次预检失败，均未作为侧栏结论证据。

第二组两种场景均记录到约 1.91MB 的首个大 WebSocket 帧，其 trace 时间分别在点击后约 0.21 秒、0.48 秒；后面仍有秒级主线程停顿。该记录不等于独立网络延迟测量，但与 trace 中持续发生的重算和布局一起，说明所测主要停顿不是单纯一直等服务端返回。没有发现页面错误或模型生成请求。

### 宿主初始渲染和滚动定位会同步触发布局

两轮独立 CPU profile 只用于归因，未纳入正式计时表。完整主题与停用 PRTS 都出现同一条热点调用链：

```text
processContent → reading.restore → followTail → scrollToBottom → metrics → scrollMetrics
```

`scrollMetrics` 读取 `clientHeight`、`scrollTop`、`scrollHeight`。它本身没有遍历正文子节点，但在新正文提交后读取这些几何属性，浏览器需要同步结算此前的样式和布局。采样中该读取附近约有 1.15 秒 / 0.73 秒，**包含浏览器强制布局，不是纯 JavaScript 计算耗时**。另有侧栏 `AnimatedRows.componentDidUpdate` 的尺寸读取，不能将这些几何读取都解释为主题扫描。

源码位置（本机源码镜像为 `/tmp/prts-harness-source-audit-20261106`）：

- `packages/client/ui-chat/src/client/chat/use-chat-scroll.ts`：首次 ready 时调用 `reading.restore()`。
- `packages/client/ui-chat/src/client/chat/use-chat-reading.ts`：没有保存位置时跟随尾部。
- `packages/client/ui-chat/src/client/chat/use-scroll-follow.ts`：`scrollMetrics()` 同步读取滚动区域几何属性。
- `packages/client/ui-chat/src/client/chat/ChatFlow.tsx`：`entries.map(...)` 生成当前历史窗口全部条目；当前实现不是视口级 DOM 虚拟列表。
- `packages/api/session-controller/src/client/sessions/session.ts`：历史窗口使用 `minMessages: 50`、`minTurns: 2`、`maxMessages: 500`。宿主已有分页，不能说一次加载全部历史；这些计数也不构成正文字符数或 DOM 渲染成本的硬上限。

### 主题明显放大样式重算，但还没有定位到单条最慢规则

停用 PRTS 仍有 1.3–1.5 秒的单个长任务，说明仅改侧栏动画无法解决。完整主题下，初始界面打开的样式重算累计由约 0.7 秒升到约 4 秒，多次大型重算分别涉及约 1.8–2.2 万个样式元素；最终实际 DOM 正文后代仍为 10101，trace 中的样式元素计数不能等同 DOM 消息数。

当前证据足以确定“宿主同步渲染 / 测量 + 主题附加样式成本”的共同影响，但不足以指定某一条选择器、某一个扫描器或单独的毛玻璃为全部根因。本轮未启用会显著放大测量成本的全量选择器统计，也未以关闭全部透明或模糊作为正式修复。

11 月 6 日的宿主导航规则收窄仅消除其中一条广域失效路径，没有减少当前历史窗口的正文量，也没有消除同步滚动测量；它仍然不是长会话加载的完整解决方案。

### 隔离结果与边界

### JS 与宿主边界

独立 CPU profile 和观察器包装仅用于归因，不混入上述正式计时。主题与停用 PRTS 均存在 `scrollMetrics → metrics → scrollToBottom → followTail → reading.restore` 的同步几何读取热点；它包含浏览器同步结算，不是主题独有的 JS 扫描。

观察器直接回调中，正文按钮适配器累计约 24ms，AI 正文适配器约 2ms，其它多数仅数毫秒。AI 正文扫描在后续 rAF 中执行，不能将 2ms 解释成整个 AI 适配器成本；但现有证据同样不支持“MutationObserver 回调本身扫描几秒”的说法。需要区分扫描和写属性的直接时间，与这些写入引发的后续样式、布局成本。

当前主题主要在宿主正文上叠加样式、表面标记与头像处理，没有另行完整解析一份相同的 Markdown 正文。DSH 当前已有历史分页和按视口激活代码高亮，但当前历史窗口仍非视口级 DOM 虚拟化。不能把新增按需代码高亮作为宿主尚未实现的优化，也不能说宿主一次性加载全部历史。
